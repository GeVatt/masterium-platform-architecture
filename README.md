# B2B E-Commerce Platform: Masterium (Core Subsystem)

## 📌 Описание проекта
Репозиторий содержит технический паспорт и описание архитектуры B2B-платформы для автоматизации учёта, аналитики и взаимодействия с контрагентами (мастерами) розничной сети «Мастериум».

* **Продакшн‑версия:** [app.masteriumgorod.ru](https://masteriumgorod.ru) *(не является частью данного репозитория, представлена архитектурная документация и демонстрационный код)*.
* **Архитектурный стиль:** Модульный монолит (stateless‑архитектура с JWT‑авторизацией).
* **Ролевая модель (RBAC):** Мастер, Администратор, Заявитель – доступ регулируется кастомными классами разрешений (`IsMasterOrAdmin`, `IsAdminUser`).

## 🏗 Архитектура бэкенда и структура компонентов

Система построена по принципу предметно-ориентированного проектирования (DDD) – каждый модуль отвечает за свою бизнес‑область. Бизнес‑логика вынесена в сервисный слой (`core.business_logic`), что обеспечивает переиспользование и тестируемость.

### Модули (Django Apps):
* `users` – управление пользователями, сессиями, JWT-аутентификация, профили мастеров (включая тарифы `TARIFF_CHOICES`).
* `appointments` – система онлайн‑записи мастеров в торговое пространство с управлением временными слотами (буфер 10 мин, интервал 10 мин), статусами (`pending`/`confirmed`/`completed`/`cancelled`) и историей изменений.
* `products` – учёт товаров мастеров, категории, движения остатков (`StockMovement`), партии (`Party`) для связки с 1С.
* `sales` – фиксация продаж, расчёт комиссии (историческая ставка `commission_rate`), пересчёт баланса мастера.
* `payments` – обработка запросов на выплаты, интеграция с балансом, автоматическое уведомление администраторов.
* `chat` – многопользовательские чаты с поддержкой стикеров, ответов, редактирования/удаления, ролей (участник/модератор), автоматическое добавление/удаление участников по тарифу (сигналы `sync_tariff_chats`).
* `notifications` – система уведомлений (email, push через WebSocket, in-app) с кастомными типами (`info`/`success`/`warning`/`error`).
* `file_imports` – импорт данных из Excel/CSV (остатки, продажи, выплаты, цены) с валидацией, частичной обработкой и логированием ошибок.
* `odata_integration` – прямой шлюз к 1С через OData API, синхронизация справочников и документов, кэширование номенклатуры в памяти.
* `yougile_integration` – двусторонняя синхронизация с внешним таск‑трекером YouGile (REST API), хранение дополнительных полей (приоритет, подзадачи) в локальной БД.
* `core` – общие модели (инструкции, мобильное приложение), вспомогательные утилиты.

## 📊 Аналитические возможности (Реализованные)

Платформа содержит встроенные инструменты для мониторинга и принятия решений:

### 1. Финансовая аналитика:
* Расчёт текущего баланса, доступных для выплаты средств, общей суммы продаж и комиссий для каждого мастера (модель `MasterBalance` с методом `recalculate()`).
* Агрегированные отчёты по продажам за период (эндпоинты `/sales/report/`, `/sales/stats/`, `/sales/monthly-stats/`).
* Визуализация на фронтенде через **ECharts** (графики продаж по месяцам, топ товаров, динамика вознаграждения vs чистой прибыли).

### 2. Операционные метрики:
* **Загрузка мастеров:** количество активных записей (`appointments`) и заполняемость временных слотов.
* **Товарные остатки:** общая стоимость, количество SKU, позиции с низким остатком (`/products/summary/`).

### 3. Регулярная отчётность:
* Ежедневный автоматический отчёт для администраторов (**Celery Beat**, задача `send_daily_reports`), включающий: новые записи, завершённые приёмы, количество и сумму продаж, новые и ожидающие запросы на выплаты. Отправка через систему уведомлений (in-app / email).

### 4. Экспорт данных:
* Возможность выгрузки данных в Excel/CSV через админку (кастомные actions для моделей `Sale`, `PaymentRequest`). Экспорт отчётов на фронтенде (через `html2pdf.js`).

## 🔄 Интеграционные интерфейсы и Data Flow

### 1. Интеграция с 1С (через OData API)
* **Клиент:** `odata_integration.client.ODataClient` – поддерживает базовую аутентификацию, повторные попытки (retry policy) и пагинацию.
* **Синхронизируемые объекты:** Справочники (Контрагенты, Договоры с процентом комиссии, Номенклатура с кэшированием) и Документы (Приходные/Расходные накладные, Чеки ККМ, Возвраты, Расход со счета/выплаты).
* **Идемпотентность:** модель `ProcessedDocument` с уникальностью по `document_ref` и мастеру предотвращает дублирование данных при повторных обменах.
* **Расписание:** запускается ежедневно через Celery Beat (`run_odata_sync`) или вручную из админки. Обработчик `odata_integration.processor.DocumentProcessor` парсит документы, создаёт/обновляет товары, движения, продажи, выплаты и пересчитывает баланс.

### 2. Импорт файлов (Excel / CSV)
* **Конвейер:** `file_imports` – загрузка файла, валидация структуры (обязательные поля), обработка с помощью **Pandas**.
* **Типы данных:** остатки товаров (stock), продажи (sales), выплаты (payments), цены (prices). Механизм: синхронная обработка (или через Celery) с поддержкой частичного успеха и логированием ошибок на уровне строк.

### 3. Интеграция с YouGile (REST API)
* **Прокси-клиент:** `integrations.yougile_proxy.YouGileAPI` – выполняет CRUD операции с задачами, досками, колонками.
* **Расширенные данные:** в локальной модели `TaskDetails` хранятся приоритет и подзадачи (синхронизируются через webhook или периодический вызов). Используется на фронтенде для Kanban-доски задач администратора.

## ⚡ Инфраструктура, Очереди и Real‑Time

Система спроектирована как **stateless** (JWT, сессии вынесены в Redis), что позволяет горизонтально масштабировать бэкенд.

### Функции Redis в проекте:
1. **Брокер Celery** – для асинхронных задач (синхронизация с 1С, импорт файлов, отправка уведомлений, генерация слотов).
2. **Channel Layer для Django Channels** – обеспечивает Pub/Sub для WebSocket-соединений (чат и уведомления в реальном времени).
3. **Кэш** – для хранения промежуточных данных (детали задач YouGile, номенклатура).

### Регламентные задачи (Celery Beat):
* Ежедневная генерация временных слотов на 7 дней вперёд (`generate_daily_slots`).
* Очистка старых импортов (`cleanup_old_imports`).
* Отправка ежедневных отчётов администраторам (`send_daily_reports`).
* Синхронизация с 1С (`run_odata_sync`).

WebSocket-соединения обслуживаются через **Daphne (ASGI-сервер)** с асинхронными потребителями для чатов и уведомлений, что обеспечивает мгновенную доставку сообщений и push-уведомлений.

## 📱 Фронтенд и Мобильный слой
* **SPA на Vue 3** с Composition API и TypeScript. Управление состоянием: **Pinia** (хранилища для аутентификации, записей, товаров, продаж, чатов). Маршрутизация — Vue Router с ролевой защитой. UI‑библиотека: **Element Plus** с кастомизированной темой.
* **Адаптивность:** CSS Grid / Flexbox + медиа‑запросы, отдельные мобильные компоненты (`MobileBottomNav`, `MobileMenu`) обеспечивают удобную работу со смартфонов.
* **Реальное время:** WebSocket-клиент для чатов и уведомлений, интеграция с Django Channels.
* **Мобильное приложение:** Реализован эндпоинт `/core/mobile-app/` для скачивания APK-файла (модель `MobileApp` в core). Инфраструктура для его хостинга и версионирования готова.
